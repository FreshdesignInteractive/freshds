FreshDS V3.0.0

Your design system is ready.

Everything in this folder is what you need to build fully designed product pages, entirely from AI.

What's in this folder
freshds-sdk/ ├── readme.html ← you are here ├── CLAUDE.md ← DS rules for Claude Code (don't touch) ├── systems/ ← the DS engine (don't touch) └── projects/ ← all your projects live here └── sample-project/ ← start here, or rename it ├── CLAUDE.md ← project context for Claude Code └── welcome.html ← a working sample page

The rule is simple: systems/ is shared and never touched. Your pages go into named subfolders inside projects/. Each project folder is independent — one per product, client, or feature area.

How to build with this
1
Create a project folder
Duplicate sample-project/ and rename it to your product or client name. Or just rename sample-project/ directly. All your pages for that product go inside it.
2
Download patterns from FreshDS
Go to freshdesign.com, browse the pattern library, configure the zones you want, then click Get this file. Drop the downloaded .html file straight into your project folder.
3
Open the SDK root in Claude Code
Launch Claude Code and open the freshds-sdk folder itself as your workspace — not just a project subfolder. This is important: Claude reads CLAUDE.md from the folder you open. Opening the SDK root means Claude loads both the DS rules at the top level and your project context simultaneously. If you open a project subfolder directly, it won't see the DS rules.
4
Describe what you want to build
Tell Claude which page to work on and what to change. Open the HTML file in a browser to preview. Iterate until it's right. Every component handles dark mode, responsive layouts, and your brand tokens automatically.
Folder conventions
Shared engine
systems/
Never modify anything inside systems/. All your pages reference it via ../../systems/. When FreshDS ships an update, replace this folder entirely.
Your work
projects/
One subfolder per product or client. Add as many pages as you need inside each. Multiple project folders can coexist side by side, all sharing the same engine.
freshds-sdk/ ├── systems/ └── projects/ ├── acme-dashboard/ ├── acme-onboarding/ └── client-xyz/
What you can build with

All components are standard web components. No framework required. They work in plain HTML files opened directly in a browser.

<fresh-button variant="primary">Save</fresh-button> <fresh-input placeholder="Search..." icon="ti-search"></fresh-input> <fresh-badge variant="success" dot>Live</fresh-badge> <fresh-navbar brand="Acme"></fresh-navbar> <fresh-modal id="confirm" heading="Confirm delete">...</fresh-modal> <fresh-stat-card value="$24.5k" label="Revenue" trend="12.4"></fresh-stat-card>
Always use <fresh-*> components. Never build raw HTML equivalents for things FreshDS already covers. If Claude suggests a raw button, input, or badge, redirect it to the DS component.
Prompting Claude effectively

Claude understands FreshDS natively. Point it at the right file and describe what you need:

"Build a settings page in projects/acme-dashboard/settings.html using FreshDS. Include profile, notifications, and billing sections. Use fresh-tabs for the section switcher and fresh-button for actions." "Add a data table to this page showing user name, email, role, and status. Status column should use fresh-badge with the right variant." "This page needs a confirmation modal when the user clicks Delete. Use fresh-modal with a danger fresh-button as the confirm action."
How CLAUDE.md files work

The SDK ships with two levels of CLAUDE.md — instruction files that Claude Code reads automatically when you open a folder.

SDK root
freshds-sdk/CLAUDE.md
Contains the full FreshDS ruleset: always use <fresh-*> components, use DS tokens for all values, path conventions, component inventory. Don't edit this file. It updates when you replace systems/.
Per project
projects/my-project/CLAUDE.md
Your project context: what the product is, who the users are, what pages exist. Short and human-written. Every project folder should have one — the sample project includes a starter template to copy.
Always open the SDK root in Claude Code — not a project subfolder. Claude reads CLAUDE.md from the folder you open and its subfolders simultaneously. Opening freshds-sdk/ means Claude loads both the DS rules and your project context at once. If you open projects/my-project/ directly, Claude only sees the project file and won't know the component rules.
freshds-sdk/ ← open THIS in Claude Code ├── CLAUDE.md ← DS rules (auto-loaded) ├── systems/ └── projects/ └── my-project/ ├── CLAUDE.md ← project context (also auto-loaded) └── dashboard.html
