General --radius-{scale}
  • •Always use radius tokens for all border-radius values in components and layouts. Never write hardcoded px values for corner rounding. The five valid tokens are --radius-sm, --radius-md, --radius-lg, --radius-xl, and --radius-full.
  • •Match token to component scale: --radius-sm for badges, chips, checkboxes, and small tags. --radius-md for buttons, inputs, selects, and dropdowns. --radius-lg for cards, modals, drawers, and side panels. --radius-xl for large floating surfaces and feature cards.
  • •Use --radius-full (9999px) exclusively for pill shapes: toggle tracks, avatar circles, status dots, and pill-style badges. Do not apply it to rectangular UI elements such as cards, modals, or input fields.
  • •Never skip radius steps to create contrast within a single screen. Mixing --radius-sm and --radius-xl on sibling elements creates visual inconsistency. Adjacent components of similar hierarchy should use the same or adjacent token steps.
  • •Documentation and spec-page chrome must use hardcoded border-radius values, never var(--radius-*) tokens. This prevents customer theme overrides from distorting documentation UI. Only the spec-viewport content area uses radius tokens.
