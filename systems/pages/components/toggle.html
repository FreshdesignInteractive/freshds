General fresh-toggle
  • •Use fresh-toggle for settings that take effect immediately without a separate save action. If the user must confirm before the change applies, use a fresh-checkbox inside a form instead.
  • •Always set a label that describes what is being toggled, not the toggle's current state. "Dark mode" is correct. "On" or "Off" is not.
  • •Match the size to the density of the surrounding context: sm for table rows and compact panels, md (default) for settings screens, lg for onboarding flows.
  • •When a toggle controls a potentially destructive setting (e.g. "Delete data on logout"), add a confirmation step before committing the change in the change event handler.
  • •Do not use a toggle to represent a multi-step process. Each toggle must represent exactly one binary setting that can be independently switched.

Accessibility

Toggle satisfies all universal accessibility concerns. Component-specific concerns are below.

ConcernRequirement
role=switchThe inner input renders role="switch" with aria-checked reflecting the current state. Screen readers announce the toggle as a switch, which is semantically distinct from a checkbox and sets the correct user expectation of immediate effect.
immediate effectBecause toggles take effect immediately, provide visible feedback near the toggle (a status badge, toast, or inline text) confirming the new state. Do not rely solely on the visual track colour to communicate the change to all users.
