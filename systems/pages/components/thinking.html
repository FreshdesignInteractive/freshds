Thinking indicator

Animated bouncing dots shown while the AI processes a request. Communicates that the system is working without exposing technical loading details. The label is customizable to match the specific operation in progress.

Thinking indicator states
Default · Generic thinking label. Use as a fallback when the operation type is unknown.
Custom labels label="..." · Match the label to the active operation. Specific labels are more reassuring than "Thinking".

General fresh-thinking
  • •Always customize the label to match the AI operation. "Analyzing your pipeline data" is more reassuring than "Thinking" because it tells users the system understood the request.
  • •Show this component in the AI response position (left-aligned in a chat thread), never inline with the user message or floating over content.
  • •Remove the thinking indicator the moment the AI response begins streaming. Leaving both visible simultaneously confuses users about the system state.
  • •Use size="sm" only in compact contexts such as an agent sidebar or inline status. Default md is the correct size for primary chat interfaces.
  • •For non-AI background operations, use fresh-spinner instead. The thinking indicator is semantically tied to AI cognition, not generic async work.

Accessibility

Thinking indicator satisfies all universal accessibility concerns. Component-specific concerns are below.

ConcernRequirement
status roleThe wrapper uses role="status" and aria-label set to the label attribute value. Screen readers announce the thinking state when it appears in the DOM.
dot animationThe bouncing dots are wrapped in aria-hidden="true". The accessible name comes from the label text only, not the animation.
