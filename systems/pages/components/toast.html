Toast

Transient notification overlays that appear in the bottom-right corner and auto-dismiss after a configurable duration. Triggered programmatically via FreshToast.show().

Toast variants
Info variant="info" · Default variant for neutral informational messages and status updates.
Success variant="success" · Confirms a completed action: save, publish, upload, invite sent.
Warning variant="warning" · Non-blocking caution: rate limit approaching, quota nearly reached.
Danger variant="danger" · Reports a recoverable failure: upload error, action could not be completed.

General fresh-toast
  • •Always trigger toasts via FreshToast.show(message, opts), not by placing <fresh-toast> directly in HTML. The static method manages the container and stacking automatically.
  • •Use toasts for non-blocking feedback on completed async actions: save, delete, share, copy. Never show a toast before an operation completes.
  • •Keep the message under 80 characters. Toasts are glanceable, not prose. Link to a log or detail page rather than embedding long error messages.
  • •Set duration: 0 for persistent toasts only when the message requires manual acknowledgment. Default 4000ms is appropriate for most confirmations.
  • •For critical errors that require user action, use fresh-alert inline or a fresh-modal instead of a toast. Auto-dismissing danger toasts may be missed.
  • •Suppress duplicate toasts: if the same message is already visible, do not show it again. Cap concurrent toasts at 3; queue or drop additional ones rather than stacking an unbounded column. Call FreshToast.show() only once per user-triggered event, never inside a loop or polling handler.

Code
JSSuccess toast
// Success confirmation after save FreshToast.show('Changes saved successfully.', { variant: 'success' });
JSDanger with custom duration
// Danger toast with longer duration FreshToast.show('Upload failed. Check your connection.', { variant: 'danger', duration: 6000 });
JSPersistent
// Persistent toast - user must manually close FreshToast.show('Processing large export, this may take a few minutes.', { variant: 'info', duration: 0 });

Accessibility

Toast satisfies all universal accessibility concerns. Component-specific concerns are below.

ConcernRequirement
live regionThe toast uses role="status" and aria-live="polite". Screen readers announce the message without interrupting the user's current focus.
auto-dismiss timingDefault 4-second duration may be too short for users who read slowly. For long or complex messages, set a longer duration or use duration: 0 to require explicit dismissal.
