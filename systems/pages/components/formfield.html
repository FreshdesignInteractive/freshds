Form Field

Layout wrapper that adds a label, hint text, and error message to any input control. Wrap every form input in a form field to ensure consistent spacing and accessible labelling.

Form field states
Basic label="..." · Label only. The minimum configuration for an accessible form field.
With hint hint="..." · A secondary line of text below the control provides context or formatting guidance.
With error error="..." · Validation failed. The error message replaces the hint and is announced to screen readers.
Required required · An asterisk appears next to the label. Can combine with hint or error.

General fresh-form-field
  • •Wrap every form input (fresh-input, fresh-select, fresh-slider) in a fresh-form-field. Never render a bare input without a label in a form context.
  • •Set error with a specific, actionable message when validation fails. The error replaces the hint automatically. Do not leave the error message vague ("Invalid input"). Say what is wrong and how to fix it.
  • •Use hint for proactive guidance that helps users fill in the field correctly. Do not use hint for post-submission validation messages; use error for those.
  • •Add required to fields the user must fill before submission. This renders the asterisk and sets the appropriate ARIA context. Pair with runtime validation: do not mark optional fields as required.
  • •Keep labels short and noun-first: "Email address", "First name", "Role". Avoid gerund phrases ("Entering your email") or question formats ("What is your role?") in labels.
Attributes
AttributeValuesDefaultDescription
labelstring-Visible label above the control. Rendered in medium weight.
hintstring-Helper text below the control. Shown in muted colour. Replaced by error when both are set.
errorstring-Validation error message. Shown in danger colour with role="alert". Takes precedence over hint.
requiredboolean-Appends a red asterisk to the label to mark the field as required.
Code
HTMLWith hint
<fresh-form-field label="Email address" hint="We'll never share your email."> <fresh-input type="email" placeholder="you@company.com"></fresh-input> </fresh-form-field>
HTMLRequired with error
<fresh-form-field label="Role" required error="Please select a role to continue."> <fresh-select placeholder="Choose role"> <option value="admin">Admin</option> <option value="editor">Editor</option> <option value="viewer">Viewer</option> </fresh-select> </fresh-form-field>

Accessibility

Form field satisfies all universal accessibility concerns. Component-specific concerns are below.

ConcernRequirement
label associationThe label text is rendered by the form field, not by the slotted input. Ensure the slotted input exposes its own aria-label or is discoverable by AT via the surrounding DOM structure. Always verify the label reads correctly in a screen reader when combining fresh-form-field with shadow DOM inputs.
error announcementThe error span renders with role="alert", causing screen readers to announce the message immediately when the error attribute changes. Only set error after the user has attempted submission or left the field. Premature errors before interaction harm usability.
