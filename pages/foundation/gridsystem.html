General .fds-grid · .fds-col-{n}
  • •Use .fds-container as the page-level max-width wrapper for all content pages. Never roll a custom max-width centering pattern with flexbox or manual margin auto. The container caps at 1280px and applies responsive horizontal padding automatically.
  • •Use .fds-grid with .fds-col-{n} children for all multi-column page-level layouts. Never write a custom display: grid; grid-template-columns: ... for page composition. Custom grid CSS is only permitted inside components or card-nested layouts.
  • •Column spans in a single .fds-grid row must sum to exactly 12. Spans that total less than 12 leave an empty gap; spans that total more than 12 wrap to the next row. Never intentionally overflow or under-fill a row.
  • •Always design mobile-first. Set a base span for the smallest viewport, then override at breakpoints: .fds-col-12 .fds-col-md-6 .fds-col-lg-4 gives full-width on mobile, half on tablet, third on desktop. Never set only a large-screen span without a mobile base.
  • •Use semantic composition layouts for recurring enterprise patterns: .fds-stack for vertical sequences of components, .fds-cluster for wrapping inline groups (tags, action buttons), .fds-sidebar-layout for fixed-width sidebar with fluid main content. These collapse correctly at --bp-md without extra media queries.
  • •Full-bleed layouts (auth split screens, hero banners, edge-to-edge image panels) are the only permitted exception to the container rule. Use flex or grid with DS tokens directly when .fds-container max-width would conflict with edge-to-edge content.
  • •The default column gap between .fds-col-{n} children is var(--space-4) (16px). Do not override this with custom gap values on .fds-grid. For tighter or looser spacing needs, use .fds-stack or nest a component-level custom grid instead of modifying the page grid gap.
