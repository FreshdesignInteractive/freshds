Foundation

Color system

A perceptual color engine generates every shade from two brand colors. Change primary and secondary in the Configurator — every token and every component updates automatically.

Architecture

Tokens are organized in three tiers. You set values at Tier 1; Tier 2 and 3 consume them. Never skip tiers — reference the nearest semantic token, not a raw primitive.

Tier 1Primitive
--color-page-bg
--primitive-primary
--scale-1..12
Raw values. Set by the Configurator or generated by the color engine. Never referenced directly in components.
Tier 2Semantic
--surface-bg
--color-interactive
--text-primary
Purpose-mapped tokens. Use these in components. They handle light/dark mode automatically via CSS cascade.
Tier 3Component
--btn-primary-bg
--input-focus-ring
--badge-primary-text
Component-scoped overrides. Use inside a specific component when a Tier 2 token isn't specific enough.

Status

Each status color generates a full 12-step OKLCH scale from the customer's chosen hex. Dark mode is derived algorithmically — the customer picks one hex and the engine outputs all tokens for both modes automatically. Each color ships with four roles: --color-{status} for icons and indicators; --color-{status}-subtle for tinted backgrounds; --color-{status}-border for borders; --color-{status}-text for readable text on subtle fills.

Data visualization

A fixed 8-color palette for charts, graphs, and data display components. Unlike brand colors, this palette is not customer-configurable — it stays consistent across all themes to ensure legibility. Each series color ships with three roles: --dv-{n} for bars, lines, dots, and pie slices; --dv-{n}-subtle for area fills and row highlights; --dv-{n}-label for annotations written on top of subtle fills.
