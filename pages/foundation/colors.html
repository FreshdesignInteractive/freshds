Generation rules OKLCH · 12-step scale
  • •Never reference a raw scale step (--primary-9, --scale-3) directly in a component. Always use Tier 2 semantic tokens (--color-interactive, --surface-subtle) or Tier 3 component tokens. Raw steps are internal to the token system and will break if the scale architecture changes.
  • •Never hardcode a hex, rgb, oklch, or hsl color value in any component or spec page. All colors must come from CSS custom properties. The only permitted exceptions are box-shadow elevation values (rgba(0,0,0,x)) and modal backdrop scrims (rgba(0,0,0,0.4)).
  • •For status patterns, always use the four-token triplet together: --color-{status}-subtle for background, --color-{status}-border for border, --color-{status}-text for text. Use --color-{status} (main) only for icons and standalone indicators, never as a background for text.
  • •Data visualization series must use --dv-1 through --dv-8 in order, starting at 1 for the first series. Never pick a dv color by hue preference. Use --dv-{n}-subtle for area fills and row highlights, --dv-{n}-label for annotations on top of subtle fills. These tokens are fixed and not customer-configurable.
  • •Dark mode is automatic when you use semantic tokens. Never write @media (prefers-color-scheme: dark) or [data-mode="dark"] selectors in a component. Semantic token values already flip between light and dark via the cascade in theme.css.
