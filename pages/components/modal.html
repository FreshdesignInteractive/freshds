General fresh-modal
  • •Use fresh-modal for focused tasks that must be completed or explicitly dismissed before the user can continue with the page beneath.
  • •Always provide a clear title via the title attribute and pair it with a primary action in the footer slot. Never present a modal with no action path.
  • •Open the modal with element.show() and close it with element.close(). Do not set the open attribute directly; use the methods to trigger the animation lifecycle.
  • •Set dismissible="false" only for critical flows where the user must choose an explicit action, such as accepting terms of service. Avoid for general confirmations.
  • •Choose size based on content: sm for simple confirmations, md for forms with a few fields, lg for rich or multi-step content. Avoid body scroll whenever possible.

Accessibility

Modal satisfies all universal accessibility concerns. Component-specific concerns are below.

ConcernRequirement
Role and labellingThe panel has role="dialog" and aria-modal="true". When a title is set, aria-labelledby links the heading element for automatic screen reader announcement.
Escape to closePressing Escape closes the modal unless dismissible="false". This is a required keyboard interaction for dialog patterns and must not be removed.
Scroll lockSets document.body.style.overflow = 'hidden' when open to prevent background scroll. Restored automatically on close. Verify cleanup if the element is removed from the DOM before close fires.
Focus managementMove focus to the first interactive element inside the modal on open. If the modal is informational with a single action, focus the action button programmatically.
