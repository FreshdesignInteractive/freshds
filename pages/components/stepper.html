Stepper

Linear progress indicator for multi-step flows. Completed steps show a checkmark, the active step is highlighted with a focus ring, and upcoming steps are muted. Supports horizontal and vertical orientations.

Stepper states
Step 1 active step="1" · All steps upcoming except step 1, which is active. No completed steps yet.
Step 2 active step="2" · Step 1 is complete (checkmark), step 2 is active, steps 3-4 are upcoming.
Step 3 active step="3" · Steps 1 and 2 complete, step 3 active. The connector line fills as steps are completed.
Vertical orientation="vertical" · Stacks steps top-to-bottom with a connecting vertical line. Better for longer step labels or narrow sidebars.

General fresh-stepper
  • •Always include a description for each step when the label alone does not clearly explain what the user will do in that step.
  • •Use horizontal orientation (default) for flows with 3-5 steps where labels are short. Switch to vertical when step labels exceed 2-3 words or when placed in a sidebar.
  • •The step attribute is 1-based. Set it to the currently active step number, not the completed count. Steps below this value render as complete.
  • •Keep step counts to 4-6 maximum. More than 6 steps should be reorganized into sections or a different navigation pattern like a sidebar with progress.
  • •Pass the entire steps array on initial render. Do not update steps mid-flow as it disorients users who are already in progress.

Accessibility

Stepper satisfies all universal accessibility concerns. Component-specific concerns are below.

ConcernRequirement
list semanticsThe stepper container uses role="list" so screen readers announce the number of steps and current position in the list.
step stateStep state (complete, active, upcoming) is currently conveyed only visually. For full accessibility, the page should announce the current step via a live region or page heading when navigation occurs.
