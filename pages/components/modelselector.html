Model Selector

Dropdown for switching AI models within an application. Shows the active model name with a CPU icon trigger and an animated dropdown listing all available models with optional capability badges.

Model selector states
Default selected="sonnet" · Closed trigger state. Shows the selected model name with a chevron. Click to open the dropdown.
Different selection selected="opus" · A different model pre-selected. The trigger always reflects the current selected attribute value.
With disabled option disabled: true · Individual models can be disabled via "disabled": true in the JSON. Disabled options render at reduced opacity and are not clickable.
Without badges no badge property · Omit the badge field from model objects to show a minimal list with just model names.

General fresh-model-selector
  • •Pass the full model list as a JSON array via the models attribute. Do not build separate selectors for each model or use radio groups for this pattern.
  • •Listen to the change event and persist the selected model key to Supabase immediately. Update the selected attribute on the component to reflect the new state after saving.
  • •Use the badge field to communicate capability tiers (e.g. "Balanced", "Fast", "Most capable"). Do not use it for pricing information - that belongs in a tooltip or info panel, not a compact badge.
  • •Use "disabled": true on model objects to reflect unavailability (e.g. no API access, region restriction). Do not remove the model from the list entirely - showing it as disabled explains why it is not accessible.
  • •Order models by capability tier from most to least capable, or by the expected usage frequency. Never alphabetize - users need to find the right model by power, not by name.
Attributes
AttributeValuesDefaultDescription
modelsJSON array of { key, name, badge?, disabled? }-List of model options. key is the internal identifier, name is displayed, badge is optional capability label, disabled blocks selection.
selectedstring (model key)-Key of the currently selected model. Falls back to the first model if the key does not match any option.
Events
EventDetailDescription
change{ key: string, name: string }Fires when the user selects a different model. key is the model identifier, name is the display label. Bubbles and is composed. Does not fire when clicking the already-selected model.
Code
HTMLBasic usage
<fresh-model-selector selected="sonnet" models='[ {"key":"opus", "name":"Claude Opus 4", "badge":"Most capable"}, {"key":"sonnet", "name":"Claude Sonnet 4", "badge":"Balanced"}, {"key":"haiku", "name":"Claude Haiku 4", "badge":"Fast"} ]'> </fresh-model-selector>
JSHandling selection
const sel = document.querySelector('fresh-model-selector'); sel.addEventListener('change', async (e) => { const { key, name } = e.detail; sel.setAttribute('selected', key); await saveUserPreference('ai_model', key); });

Accessibility
ConcernRequirement
listbox roleThe dropdown has role="listbox" and each option has role="option" with aria-selected. Screen readers can navigate the list with arrow keys once the dropdown is open.
escape to closePressing Escape while the dropdown is open closes it without changing the selection. Focus returns to the trigger button so the user can continue without losing their position.
