Timeline

Vertical chronological list for activity feeds, audit logs, and process history. Each item shows a timestamp, title, optional description, and a variant-colored icon dot connected by a vertical line.

Timeline variants
Activity feed · Full items with icon, variant color, title, description, and timestamp. Used for deployment logs and audit trails.
Compact · Title and timestamp only, no description. Use for dense feeds or when events are self-explanatory.
All status variants · Each variant maps to a semantic status color. Neutral uses a muted surface.

General fresh-timeline
  • •Always order items from most recent to oldest (newest first). Users scanning an activity feed expect the latest event at the top.
  • •Match variant to the event outcome: success for completed/healthy events, danger for failures, warning for degraded or pending states, primary for key milestones, neutral for informational events.
  • •Omit description for events that are self-explanatory from the title alone. Dense description text on every item reduces scannability.
  • •Use relative timestamps ("2 min ago", "Yesterday") for recent events and absolute timestamps ("Apr 19, 2024") for events older than a week. Never mix formats in the same timeline.
  • •For long feeds, paginate or lazy-load items. Rendering hundreds of timeline entries at once degrades performance and overwhelms users. Show 10-20 items initially with a "Load more" control.
  • •When the items array is empty or not yet loaded, do not pass an empty array and leave the component blank. Either omit the component entirely and render a dedicated empty state with an explanatory message, or pass a single neutral item explaining the absence (e.g. "No activity yet. Events will appear here once recorded.").

JSBuilding items from API data
// Build items array from API response const items = events.map(ev => ({ timestamp: formatRelativeTime(ev.createdAt), title: ev.summary, icon: iconForEventType(ev.type), variant: variantForStatus(ev.status) })); document.querySelector('fresh-timeline') .setAttribute('items', JSON.stringify(items));

Accessibility

Timeline satisfies all universal accessibility concerns. Component-specific concerns are below.

ConcernRequirement
color meaningDot variant colors convey status. Never rely on color alone. Always include a descriptive title that communicates the event outcome without requiring color perception.
timestampRelative timestamps like "2 min ago" should use a datetime attribute or tooltip with the absolute ISO timestamp for users who need precise timing information.
