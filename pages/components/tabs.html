Tabs

Horizontal tab bar for switching between related views. Emits a change event with the newly active key. Connect it to your panel visibility logic. Fully keyboard navigable.

Tabs states
Default (md) size="md" · Underline indicator on active tab. 38px tab height. Connect the change event to show/hide panels.
Overview panel content
With badges and disabled badge / disabled · Badge shows a count chip on the tab. Disabled tab is non-interactive at 38% opacity.
Sizes size="sm" / "md" / "lg" · sm 32px, md 38px (default), lg 44px. Font and padding scale proportionally.

General fresh-tabs
  • •Always listen to the change event and update panel visibility in the handler. Never rely on CSS-only display toggling for panel switching.
  • •Use badge within a tab item only for unread counts or status indicators, not for decorative labels. Use fresh-topbar-menu for top-level navigation where badge support is not needed.
  • •Set active to the key of the initially selected tab on page load. Do not leave it blank or the tab bar will render with no active state.
  • •Keep tab labels short (one or two words). If a label requires more than three words, consider restructuring the IA rather than wrapping the tab text.
  • •Do not mix fresh-tabs and fresh-topbar-menu on the same page. Choose one tab style per product context for visual consistency.

Accessibility

Tabs satisfies all universal accessibility concerns. Component-specific concerns are below.

ConcernRequirement
roleThe tab list has role="tablist". Each button has role="tab" and aria-selected reflecting its active state.
keyboard navigationArrow Left/Right moves focus between tabs. Enter or Space activates the focused tab. Disabled tabs are skipped in the Arrow navigation cycle.
panel linkageAdd role="tabpanel" and aria-labelledby pointing to the active tab's ID on each content panel for correct screen reader announcement.
