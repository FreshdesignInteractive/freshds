AI action rules Click any rule to edit
Primary variant="primary"
  • • Use variant="primary" for the single highest-priority action within a given UI context.
  • • Limit to one primary button per view — avoid competing primaries side by side.
  • • Label with a strong action verb: "Save", "Submit", "Create" — not "OK" or "Yes".
  • • Primary button should initiate the terminal committing action of the current flow.
  • • Do not use primary inside notification banners or toasts — use ghost or inline links there instead.
Secondary variant="secondary"
  • • Use variant="secondary" for the second most important action, typically paired with a primary (e.g. Cancel + Save).
  • • Can appear alone when the action is important but not the page's main CTA.
  • • Prefer secondary over ghost when the action needs to stand out against surrounding content.
  • • Do not use secondary for destructive actions — use variant="danger" instead.
Tertiary variant="ghost"
  • • Use variant="ghost" for low-emphasis, optional, or repeated controls: toolbars, pagination, filters, icon buttons.
  • • Ideal for secondary actions inside cards and controls embedded inline within text flows.
  • • Always ensure adequate surrounding spacing so ghost buttons remain recognisable as interactive.
  • • Do not use ghost as the sole action in a dialog or empty state — the action lacks visual weight in that context.
Destructive variant="danger"
  • • Use variant="danger" for irreversible or high-risk operations: delete, remove access, clear data, revoke permissions.
  • • Always follow a destructive action with a confirmation dialog — never act immediately on first click.
  • • Never place a danger button as the primary page-level CTA — reserve it for explicitly destructive confirmation flows.
  • • Label with the specific action: "Delete account", "Remove user" — not "Confirm" or "Yes" for a danger-variant button.
AI Action variant="ai"
  • • Use variant="ai" exclusively for AI-generated or AI-assisted actions: generate content, summarise, explain, suggest.
  • • Always prefix the label with a sparkle icon (<i class="ti ti-sparkles">) to visually signal AI involvement.
  • • Do not use variant="ai" for standard CRUD operations — even if an AI model runs in the background.
  • • Disable when the model is unavailable or rate-limited; surface a status message near the button explaining why.
  • • Label with clear action language: "Generate draft", "Summarise", "Explain this" — not just "AI" as the label.
Accessibility

Button satisfies all universal accessibility concerns — role, accessible name, keyboard, focus ring, colour contrast, icon decoration, disabled state, and touch target. The only concern specific to this component is below.

Concern Requirement
loading state Sets aria-busy="true" during loading. Pair with an updated aria-label like "Saving…" to give spoken status context beyond the spinner visual.
