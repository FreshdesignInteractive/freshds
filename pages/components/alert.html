Alert

Inline notification banners for important messages that do not require an immediate response. Use for system status, warnings, or confirmations within a page context.

Alert variants
Info variant="info" · Neutral informational messages: updates, hints, feature announcements.
A new version of FreshDS is ready. Refresh to apply. You have unsaved changes. They will be lost if you navigate away.
Success variant="success" · Positive confirmations: saved changes, completed actions, successful deployments.
Your changes are live at production.freshdesign.com. Your display name and avatar have been saved.
Warning variant="warning" · Caution messages: rate limits, deprecation notices, approaching thresholds.
You have used 87% of your monthly API quota. This integration will be deprecated on July 1. Migrate before then.
Danger variant="danger" · Error conditions and critical failures requiring attention.
Compilation error on line 42. Check the error log. Unable to connect to the database. Retrying in 30 seconds.

General fresh-alert
  • •Use alerts for passive information that does not block the user. If the user must take immediate action before proceeding, use a modal instead.
  • •Match variant to the true severity: reserve danger for actual errors, not for notices that are merely inconvenient. Overusing danger desensitizes users.
  • •Add a title when the alert has more than one sentence. The title gives screen reader users an immediate summary before the body is read.
  • •Use dismissible only when dismissal is safe: the user will not lose information and the state will not return unexpectedly. For persistent system errors, omit dismissible.
  • •Place alerts at the top of the relevant content area, not floating in a corner. For transient confirmations triggered by user actions, use fresh-toast instead.
  • •Choose fresh-alert when the message is persistent and contextual to a specific page region (e.g. a form validation banner, a subscription notice). Choose fresh-toast when the message is transient, triggered by a completed action, and not tied to a specific region. Never use both to communicate the same event.

Accessibility

Alert satisfies all universal accessibility concerns. Component-specific concerns are below.

ConcernRequirement
live regionThe alert wrapper carries role="alert" and an aria-label matching the variant (e.g. "Success"). Screen readers announce it immediately when injected into the DOM.
dismiss buttonThe close button has aria-label="Dismiss". Focus must not be lost when the alert is removed; return focus to the triggering element or the nearest logical container.
