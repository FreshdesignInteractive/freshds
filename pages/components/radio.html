Radio

Single-selection control for mutually exclusive options. Group radios with a shared name attribute so only one can be selected at a time.

Radio states
Unselected · Default resting state. The circle is hollow with a border.
Selected checked · The chosen option. The circle border thickens and fills with the interactive colour.
Disabled disabled · Interaction blocked. Opacity drops to 40%. Can apply to individual items in a group.

General fresh-radio
  • •Use fresh-radio when the user must select exactly one option from a small set (2 to 7 items). For longer lists, use fresh-select instead.
  • •Always give every radio in a group the same name attribute. Without a shared name, multiple options can be selected simultaneously, breaking the mutual-exclusion guarantee.
  • •Set a unique value on each radio so the change event payload identifies which option was selected. Do not leave value unset on items in the same group.
  • •Always set checked on one item to provide a default selection. Leaving a radio group with no default forces the user to make a choice before the form can be submitted.
  • •Wrap radio groups in a fresh-form-field with a label so the group has an accessible name. A bare list of radios without a group label fails WCAG 1.3.1.
Attributes
AttributeValuesDefaultDescription
labelstring-Visible label text rendered to the right of the circle.
valuestring-Identifies this option in the change event detail and the native radio group.
namestring-Groups radios together. All radios sharing a name are mutually exclusive. Required for correct behaviour.
checkedboolean-Pre-selects this radio on render. Only one item in a group should carry this attribute.
disabledboolean-Prevents interaction on this item only. Other items in the same group remain interactive.
Events
EventDetailDescription
change{ value: string, name: string }Fired on the radio that became selected. value and name match the element's attributes. Only fires when a radio transitions to checked, not when it is deselected. Bubbles and is composed.

Accessibility

Radio satisfies all universal accessibility concerns. Component-specific concerns are below.

ConcernRequirement
group semanticsRadio buttons that share a name must be visually and semantically grouped under a common label so the group purpose is announced by screen readers. Wrap in a container with a heading or use fresh-form-field with a label attribute.
keyboard navigationBecause each fresh-radio is a separate custom element, arrow-key navigation between items in a group is not automatic. Callers should use Tab to move between groups and may need to implement arrow-key handling if native radio-group keyboard behaviour is required.
