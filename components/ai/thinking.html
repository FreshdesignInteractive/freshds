Thinking

Animated indicator shown while the AI processes a request. Three bouncing dots with a contextual label reassure users that a response is on the way.

General fresh-thinking
  • •Show fresh-thinking immediately after a prompt is submitted. Do not leave a blank space while waiting for the first token.
  • •Replace the thinking indicator with fresh-ai-response as soon as the first token arrives. Never show both simultaneously.
  • •Set label to describe what the AI is doing: "Searching documents", "Running analysis", "Writing code". Context-specific labels reduce perceived wait time.
  • •Use size="sm" inside compact containers like sidepanels, inline chat, or card footers. Use md in main conversation areas.
  • •If an error occurs during processing, remove the thinking indicator and surface a clear error message. Never leave the thinking state visible after a failure.

JSShow then replace
const area = document.getElementById('chat');
const t = document.createElement('fresh-thinking');
t.setAttribute('label', 'Writing summary');
area.appendChild(t);

const text = await callAI(prompt);
t.remove();

const msg = document.createElement('fresh-ai-response');
msg.setAttribute('role', 'assistant');
msg.textContent = text;
area.appendChild(msg);

Accessibility

Thinking satisfies all universal accessibility concerns. Component-specific concerns are below.

ConcernRequirement
Status roleThe wrapper element has role="status" and aria-label set to the current label value. Screen readers announce the state when the element appears.
AnimationThe bouncing dots are marked aria-hidden="true". The text label carries the accessible meaning independently.
Reduced motionWrap in a prefers-reduced-motion query at the app level if users have set that system preference. The label remains visible without animation.
